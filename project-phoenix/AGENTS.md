# Project Phoenix contributor instructions

- Prefer hands-on implementation over lengthy theory.
- Keep changes small, reviewable, and testable; run relevant tests after code changes and report actual results.
- Preserve unrelated repository work. Do not use destructive Git operations without explicit authorization.
- Never commit secrets. Keep local environment files, virtual environments, and runtime databases ignored.
- Avoid unnecessary dependencies, paid services, and agent frameworks until the basic application works.
- Explain important architectural choices and keep documentation readable.
- Use deterministic tests for core behavior. Mark missions complete only with evidence.
